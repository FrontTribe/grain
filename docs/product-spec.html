Product Specification

Grain — code provenance layer

A tool that shows how much of a repository was human-written, how much was AI-assisted, and whether changes followed the project's own rules. Signals, not verdicts.

Version 0.1 draft Status pre-MVP Owner solo / open source MIT core Target MVP ~2 weeks

00 Overview

Grain reads a git history and produces a provenance report: the share of code that is human-authored vs AI-assisted, broken down by directory and change, with a confidence level on every claim. It ships as a single-binary CLI plus a GitHub Action, and surfaces its findings where developers already look — a README badge, a PR check, and a PROVENANCE.md file committed to the repo.

Positioning in one line

"See the grain of your codebase — how it was made, not just what it is." Grain is to authorship what a coverage badge is to tests: a lightweight, in-repo signal that becomes a norm because it is free, fast, and visible.

Elevator context

In 2026 autonomous agents commit directly to repos and maintainers have grown wary of undeclared AI code. Between "AI writes freely" and "maintainers demand transparency" sits an unmet need: a neutral instrument to measure provenance. Grain is that instrument. It does not judge, block by default, or accuse — it reports what the history shows, with honest uncertainty.

01 Problem & why now

Two independently-true trends collided this year, and their intersection is the product wedge:

Trend A — AI commits autonomously

  • Agents open PRs, log tool activity, and push commits directly.
  • A diff in a tree is no longer presumed human.
  • Reviewers lack a fast way to see "how much of this is generated."

Trend B — Maintainers turned wary

  • Projects are rewriting contribution policy to require AI disclosure.
  • The stated sentiment is explicitly "AI-skeptical / wary."
  • But policy has no tooling — disclosure is honor-system today.

The gap is trust, and trust needs measurement. Grain gives policy a set of eyes: it turns "please disclose AI use" from an honor-system request into an automatic, visible signal.

Why a solo dev can win this
The core is git-native and heuristic-first — buildable in weeks, not quarters. It is culturally charged (great launch energy), self-distributing (every badge markets it), and has a clean open-core seam (single-repo local = free; org-wide policy + compliance = paid).

03 Goals & non-goals

Goals

  • Measure and communicate code provenance honestly, with confidence levels.
  • Zero-friction adoption: one command, one Action, one badge.
  • Privacy-first: the free tool runs fully local; code never leaves the machine.
  • Become a norm — the "coverage badge" of the AI era.
  • Give maintainers a calm, neutral transparency signal.

Non-goals

  • Not an anti-cheat / plagiarism detector, and not marketed as one.
  • Not a surveillance tool for punishing developers.
  • Not a code-quality linter (orthogonal to correctness).
  • Not a hard merge-blocker by default (opt-in only).
  • Not a claim of certainty from inference — ever.
North-star principle
Grain reports signals, not verdicts. Copy, output, and defaults all reinforce this. It is the single decision that separates adoption from backlash.

04 Core concepts & terminology

TermDefinition
ProvenanceThe origin story of a change: who/what authored it and under what process.
Unit of analysisThe commit. Scores aggregate up to file → directory → PR → repo, weighted by lines changed.
ai_likelihoodA 0–1 estimate that a unit was AI-generated/assisted.
basisHow the estimate was reached: declared (explicit signal) or inferred (behavioral).
confidence0–1 trust in the estimate. Declared → up to 1.0. Inferred → capped (default 0.7). A hard product rule.
classBucketed label for display: human, ai_assisted, ai_authored, unclassified.
grain mixRepo-level summary percentages (e.g. 71% human / 24% AI / 5% unclassified).
attention flagA contextual concern (e.g. AI touched a human-owned path) — separate from ai_likelihood.

05 Detection engine

The engine extracts signals from each commit, scores an ai_likelihood and confidence, then aggregates. Signals are grouped in three tiers by trustworthiness.

5.1 — Tier A: declared signals high confidence

Deterministic, machine-declared evidence. When present, they dominate the score.

  • Co-Authored-By: trailer matching a known agent (Claude, Copilot, Cursor, Codex, Devin, …).
  • Author/committer is a known bot account (*[bot], configurable allow/deny list).
  • Explicit trailers: Generated-by:, Assisted-by:, AI-Assisted: true.
  • Self-declaration labels on a PR/commit (grain:ai, grain:human) — manual override.

5.2 — Tier B: inferred behavioral signals inferred · capped

Probabilistic tells from the shape of the change. They never push confidence past the cap.

SignalWhat it looks atDirection
Diff uniformityEntropy of the diff; AI edits tend to be uniform, complete, comment-dense.↑ AI
Burst timingLarge diff after a short session; many commits in a tight window.↑ AI
Message stylePerfectly-formed conventional commits, generic bodies, telltale phrasing.↑ AI (weak)
Net-new vs editLarge greenfield files vs incremental hand-edits.↑ AI
Formatting regularityWhitespace / structural consistency beyond repo norm.↑ AI (weak)
Decision — inference is honest by design
Tier B is intentionally weak and clearly labeled. If Tier A is absent, Grain says "inferred, low confidence" rather than pretending to know. This protects real humans who happen to write clean code.

5.3 — Tier C: contextual modifiers (attention, not classification)

  • CODEOWNERS check — an ai_assisted change touching a human-owned path raises an attention flag, not the AI score.
  • Convention deviation — the change departs from the repo's own learned style baseline.

5.4 — Scoring model

extract signals→ declared? set score+conf→ else infer (cap conf)→ bucket class→ aggregate by lines 
# per-commit, pseudocode
if declared_signals:
    ai_likelihood = max(weight(s) for s in declared_signals)  # e.g. 0.98
    confidence    = 0.95
    basis         = "declared"
else:
    ai_likelihood = logistic(Σ wᵢ · featureᵢ)                # Tier B
    confidence    = min(inferred_confidence, CAP)          # CAP=0.70
    basis         = "inferred"

class = bucket(ai_likelihood, confidence)                     # human / ai_assisted / ai_authored / unclassified
# unclassified when confidence is too low to bucket

Repo/dir/PR aggregates are line-weighted means of member commits, carrying a blended confidence. MVP uses hand-tuned weights; weights are versioned in the schema so scores are reproducible and explainable.

5.5 — Optional local model pass

For ambiguous diffs only, an optional small classifier (local GGUF via an embedded runtime, or a heuristic-only fallback) can refine Tier B. It runs client-side; code never leaves the machine. Off by default in MVP; the heuristic engine stands alone.

06 Outputs

One input (a repo or a diff), three outputs. No dashboard required for the free tool.

6.1 — The badge

A shields.io-compatible endpoint (JSON) or static SVG. Modes: mix (e.g. "24% AI-assisted"), owned ("human-owned"), policy ("review needed"). Every badge in a README is a distribution surface.

# README.md
![grain](https://img.shields.io/endpoint?url=https://.../grain.json)

6.2 — The PR check

Posted by grain[bot] as a PR comment + a status check. Calm, itemized, framed as signals.

grain report · PR #482
› 62% of +214 lines carry AI-authorship signals  (1 Co-Authored-By: Claude)
› 2 files touch src/auth/ — human-owned per CODEOWNERS
› convention check: 3 deviations from repo style
policy: AI share > 40% in a human-owned path → 1 human review requested

6.3 — PROVENANCE.md (the nutrition label)

A generated, committable file: repo-level mix, per-directory breakdown, generation timestamp + engine version. Human-readable and diff-friendly so provenance itself is versioned.

Decision — machine format alongside
Each run also emits grain.json (see §09) as the machine source of truth; PROVENANCE.md is the human render of it.

07 CLI specification

Single static binary, no runtime deps for the user. Distributed as a Go binary via Homebrew / go install / curl script, plus a thin npm wrapper so npx grain works.

CommandPurposeExit
grain scanScan repo/range → write PROVENANCE.md + grain.json, print summary.0
grain checkCI/PR mode: analyze the diff, print PR markdown, exit non-zero on policy breach.0 / 1
grain badgeEmit shields endpoint JSON or SVG.0
grain explain <sha>Show which signals classified a commit and why.0
grain initScaffold .grain.toml.0

Key flags

--since <date> · --range <a..b> · --format json|md|text · --config <path> · --model off|local|<path> · --fail-on <rule> · --no-inference

Config — .grain.toml

[policy]
ai_threshold        = 0.40            # PR attention threshold
require_review_over = 0.40
human_owned         = ["src/auth/**", "src/payments/**"]

[detection]
inference   = true
local_model = "off"                   # off | local | <gguf path>
agents      = ["claude", "copilot", "cursor", "codex", "devin"]
bot_authors = ["*[bot]"]

[report]
badge  = "mix"                       # mix | owned | policy
output = "PROVENANCE.md"

Exit codes: 0 ok · 1 policy violation (for CI gating) · 2 error.

08 GitHub Action

A thin wrapper around grain check. Runs on pull_request, posts/updates one sticky comment, sets a status check, and can refresh the badge endpoint on main.

- uses: grain-dev/grain-action@v1
  with:
    fail_on: policy        # comment-only by default; opt-in to gating
    config:  .grain.toml
Default posture
The Action comments, does not block, out of the box. Gating is a deliberate opt-in (fail_on). This keeps first contact non-hostile.

10 Architecture (MVP)

git (go-git)→ commit iterator→ signal extractors→ scorer→ aggregator→ renderers (md · json · badge · pr)
  • Language: Go — static binary, fast, trivial to ship as CLI + Action. decision · Rust is the alternative
  • Git access: go-git (pure Go, no libgit2 dependency).
  • No server in MVP. Everything runs in the repo/CI. The badge is a static JSON committed or served from Pages.
  • Extensible signals: each extractor is an interface, so new agents/tells are additive.
  • Optional model: pluggable local inference behind a flag; heuristics work standalone.

11 Trust & privacy principles

  • Local-first. The free tool never transmits source code. All analysis is on-device / in-CI.
  • Signals, not verdicts. Output language is probabilistic and non-accusatory by contract.
  • Confidence caps on inference. Grain refuses to sound certain when it is guessing.
  • Explainability. grain explain shows the exact signals behind any classification.
  • Reproducibility. Scores are pinned to an engine + weights version in grain.json.
  • Human override. A grain:human / grain:ai declaration always wins over inference.

12 Threat model & honest limits

ConcernRealityResponse
Stripping Co-Authored-By to hide AI useTrivially possible; falls back to weak inference.Grain is a transparency tool for cooperative repos, not anti-cheat. Stated plainly in docs; never over-claimed.
False positives on clean human codeReal risk with inference alone.Confidence cap + "signals" framing + never block by default. Declared signals preferred.
"Surveillance tool" perceptionReputational, could kill adoption.Non-goals are explicit; defaults are comment-only; positioning is maintainer-transparency, not dev-policing.
Adversarial rewriting to defeat heuristicsPossible with effort.Out of scope by design; Grain measures the honest signal that exists, not a guarantee.
Honesty as a feature
Naming these limits openly is part of the product. Overclaiming (an "AI detector that catches cheaters") is exactly what would trigger backlash and false-positive drama. Grain wins by being trustworthy, not omniscient.

13 Open-core boundary

The line: anything that runs on a single repo, locally, is MIT and free. Anything server-side, multi-repo, persistent, or policy-as-a-service is paid.

TierPriceIncludesFor
grain CLIMIT · freeCLI, Action, badge, PROVENANCE.md, local scan/check/explain, full engine.Solo devs, OSS maintainers
grain Cloud$ / seatOrg dashboard, trend history, merge-policy engine, multi-repo rollups, Slack/PR gating.Teams shipping with agents
grain Audit$$Signed provenance ledger, EU AI Act / SOC2 export, SSO, retention, on-prem.Regulated / enterprise

Licensing: core MIT (maximizes adoption + trust). Cloud/Audit are proprietary hosted services. The engine staying fully open is a feature, not a giveaway — it is what makes the numbers credible.
