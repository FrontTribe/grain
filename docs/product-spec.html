Product Specification

Grain — code provenance layer

A tool that shows how much of a repository was human-written, how much was AI-assisted, and whether changes followed the project's own rules. Signals, not verdicts.

Version 0.1 draft Status pre-MVP Owner solo / open source MIT core Target MVP ~2 weeks

00 Overview

Grain records which lines an AI agent writes as it writes them, signs that into git as a note bound to the commit, and produces a provenance report: the share of code that is human-authored vs AI-assisted, where the AI-written code landed (critical paths, review evidence), what happened to it later (rework), with a confidence level on every claim. It ships as a single-binary CLI plus a GitHub Action, surfaces its findings where developers already look — a README badge, a PR check, a PROVENANCE.md file committed to the repo — and, as grain Cloud, watches a workspace of repositories on every push.

Status — 2026-09-15
Everything in this spec marked shipped exists and runs on grain's own repository; §15 lists what is next. The illustrative figures of the v0.1 draft are replaced by real ones where they matter.

Positioning in one line

"See the grain of your codebase — how it was made, not just what it is." Grain is to authorship what a coverage badge is to tests: a lightweight, in-repo signal that becomes a norm because it is free, fast, and visible.

Elevator context

In 2026 autonomous agents commit directly to repos and maintainers have grown wary of undeclared AI code. Between "AI writes freely" and "maintainers demand transparency" sits an unmet need: a neutral instrument to measure provenance. Grain is that instrument. It does not judge, block by default, or accuse — it reports what the history shows, with honest uncertainty.

01 Problem & why now

Two independently-true trends collided this year, and their intersection is the product wedge:

Trend A — AI commits autonomously

  • Agents open PRs, log tool activity, and push commits directly.
  • A diff in a tree is no longer presumed human.
  • Reviewers lack a fast way to see "how much of this is generated."

Trend B — Maintainers turned wary

  • Projects are rewriting contribution policy to require AI disclosure.
  • The stated sentiment is explicitly "AI-skeptical / wary."
  • But policy has no tooling — disclosure is honor-system today.

The gap is trust, and trust needs measurement. Grain gives policy a set of eyes: it turns "please disclose AI use" from an honor-system request into an automatic, visible signal.

Why a solo dev can win this
The core is git-native and heuristic-first — buildable in weeks, not quarters. It is culturally charged (great launch energy), self-distributing (every badge markets it), and has a clean open-core seam (single-repo local = free; org-wide policy + compliance = paid).

03 Goals & non-goals

Goals

  • Measure and communicate code provenance honestly, with confidence levels.
  • Zero-friction adoption: one command, one Action, one badge.
  • Privacy-first: the free tool runs fully local; code never leaves the machine.
  • Become a norm — the "coverage badge" of the AI era.
  • Give maintainers a calm, neutral transparency signal.

Non-goals

  • Not an anti-cheat / plagiarism detector, and not marketed as one.
  • Not a surveillance tool for punishing developers.
  • Not a code-quality linter (orthogonal to correctness).
  • Not a hard merge-blocker by default (opt-in only).
  • Not a claim of certainty from inference — ever.
North-star principle
Grain reports signals, not verdicts. Copy, output, and defaults all reinforce this. It is the single decision that separates adoption from backlash.

05 Detection engine

The engine extracts signals from each commit, scores an ai_likelihood and confidence, then aggregates. Signals are grouped in four tiers by trustworthiness; the top tier is recorded, not detected.

5.0 — Tier 0: attested, captured at the source ground truth · shipped

Detecting AI code after the fact is unreliable (see the calibration study). So grain records it when it happens:

  • grain hook claude runs from Claude Code's PostToolUse hook and appends the lines the agent just wrote, as content hashes, to .grain/ai-edits.jsonl (gitignored, transient, never text).
  • On commit, grain attest (post-commit hook) matches the commit's added lines against the ledger and writes the note: Provenance, AI-Lines: n/m, AI-Hashes, signed with the developer's Ed25519 key and bound to the SHA. Matched lines are consumed so nothing is attested twice.
  • grain blame <file> resolves provenance per line; grain verify checks every note (valid / invalid / unsigned; trust via .grain/signers). A note that is edited or moved to another commit fails.
  • grain annotate <sha> --ai|--human|--assisted writes a signed note by hand.
Decision — attested beats everything
A line-attested commit counts by its true AI share (AI-Lines), not all-or-nothing. Lines nobody attested are shown as human, never claimed as AI. A valid signature proves who wrote the note and that it hasn't changed, not that the claim is true; that is stated everywhere the number appears.

5.1 — Tier A: declared signals high confidence · shipped

Deterministic, machine-declared evidence. When present, they dominate the score.

  • Co-Authored-By: trailer matching a known agent (Claude, Copilot, Cursor, Codex, Devin, …).
  • Author/committer is a known bot account (*[bot], configurable allow/deny list).
  • Explicit trailers: Generated-by:, Assisted-by:, AI-Assisted: true.
  • Self-declaration labels on a PR/commit (grain:ai, grain:human) — manual override.

5.2 — Tier B: inferred signals inferred · capped · shipped

Probabilistic tells from the content and shape of the change. They never push confidence past the cap.

SignalWhat it looks atDirection
Content classifierTen lexical features of the added code (comment density, identifier length, error-handling idioms, …) through a logistic model. The global fit did not generalize across repositories; grain calibrate fits per-repo weights from that repo's declared commits (.grain/model.json).↑ / ↓ AI
Diff uniformityEntropy of the diff; AI edits tend to be uniform, complete, comment-dense.↑ AI
Burst timingLarge diff after a short session; many commits in a tight window.↑ AI
Message stylePerfectly-formed conventional commits, generic bodies, telltale phrasing.↑ AI (weak)
Net-new vs editLarge greenfield files vs incremental hand-edits.↑ AI
Formatting regularityWhitespace / structural consistency beyond repo norm.↑ AI (weak)
Decision — inference is honest by design
Tier B is intentionally weak and clearly labeled. If Tier A is absent, Grain says "inferred, low confidence" rather than pretending to know. This protects real humans who happen to write clean code.

5.3 — Tier C: contextual modifiers (attention, not classification) shipped

  • Human-owned paths — an ai_assisted change touching a policy human_owned path raises an attention flag, not the AI score.
  • Risk — AI-written lines (attested or declared; never inferred) in critical paths without review evidence, per path and per commit (hotspots). The CLI reads evidence from git; Cloud also asks the GitHub PR API whether the commit belongs to a pull request and who approved it.
  • Outcomes — rework rate of AI vs human lines from the same line-attested commits, with fix/revert tagging and median commits-to-rework.
  • Convention deviation — the change departs from the repo's own learned style baseline. not shipped

5.4 — Scoring model

extract signals→ declared? set score+conf→ else infer (cap conf)→ bucket class→ aggregate by lines 
# per-commit, pseudocode
if attested_note and signature_ok:
    ai_likelihood = 0.98 if note.provenance in (ai, assisted) else 0.02
    confidence    = 0.95
    basis         = "attested"
    ai_frac       = note.ai_lines / note.total_lines             # line-level share, when recorded
elif declared_signals:
    ai_likelihood = max(weight(s) for s in declared_signals)  # e.g. 0.98
    confidence    = 0.95
    basis         = "declared"
else:
    ai_likelihood = logistic(Σ wᵢ · featureᵢ)                # Tier B
    confidence    = min(inferred_confidence, CAP)          # CAP=0.70
    basis         = "inferred"

class = bucket(ai_likelihood, confidence)                     # human / ai_assisted / ai_authored / unclassified
# unclassified when confidence is too low to bucket

Repo/dir/PR aggregates are line-weighted means of member commits (an attested commit contributes ai_frac of its lines), carrying a blended confidence. Weights are versioned in the schema (w1 behavioural baseline, w2-content, w2-content-fit per repo) so scores are reproducible and explainable.

5.5 — Calibration shipped

grain eval scores the content classifier against a repo's declared commits (the labels git already has); grain calibrate fits per-repo weights and writes .grain/model.json, which the scorer picks up automatically. The study that motivated this is published, including the negative result (leave-repos-out AUC below chance for a single global model). The optional local GGUF model pass from the v0.1 draft is deferred; the lexical classifier stands alone and runs client-side.

06 Outputs

One input (a repo or a diff), four outputs from the CLI; a fifth, the Cloud workspace, on top. No dashboard required for the free tool.

6.1 — The badge

A shields.io-compatible endpoint (JSON) or static SVG. Modes: mix (e.g. "24% AI-assisted"), owned ("human-owned"), policy ("review needed"). Every badge in a README is a distribution surface.

# README.md
![grain](https://img.shields.io/endpoint?url=https://.../grain.json)

6.2 — The PR check

Posted by the Action as one sticky PR comment + a grain/provenance status. Calm, itemized, framed as signals: the AI share per path, one policy line per thing the policy noticed, then the Security and Dependencies sections for the change set. The comment grain left on its own test PR:

Provenance report · PR #3
100% AI-assisted · 1 commit, 11 lines changed
sandbox/                     0% human · 100% AI

policy  change set above the 40% AI threshold → review suggested
policy  1 security finding in AI-written lines → a human should look   (security = "warn")
policy  1 added dependency not on the registry → a human should look   (dependencies = "warn")

security      7b49393 sandbox/fetch.py  TLS verification disabled (high)   AI
dependencies  leftpadd-utilz   pypi   AI   not found
              requests         pypi   AI   5691 days old

Three gates, all opt-in to block: the AI threshold and human-owned paths (fail_on: policy), security and dependencies in .grain.toml (off | warn | block, default warn). "block" fails grain check; with fail_on: policy that is a failed status a branch rule can require. A maintainer can still merge.

6.3 — PROVENANCE.md (the nutrition label)

A generated, committable file: repo-level mix, per-directory breakdown, an Outcomes table (AI vs human rework from the same attested commits), a Risk section (critical-path AI lines without review evidence, per path, with hotspot commits), a Security section (pattern matches joined with provenance, worst first) and a Dependencies table (each package the range added, who added it, and the registry's answer), generation timestamp + engine version. Human-readable and diff-friendly so provenance itself is versioned.

Decision — machine format alongside
Each run also emits grain.json (see §09) as the machine source of truth; PROVENANCE.md is the human render of it.

6.4 — Signed attestations shipped

Git notes on refs/notes/grain, one per commit, signed with the author's Ed25519 key (grain key) and bound to the SHA. Plain text, public format, verifiable offline by anyone with a clone. They travel with the repository (git push origin refs/notes/grain) and Cloud reads them straight from GitHub.

6.5 — grain Cloud shipped

  • Scans on every push through the GitHub App (webhook → installation token → scan → ingest); CLI-scanned repos arrive via grain push with an ingest token.
  • Dashboard: workspace overview, repositories, per-repo page with provenance basis, Outcomes, Risk, Security and Dependencies cards, trends, policy (threshold, human-owned paths, merge behaviour), activity.
  • Alerts by email (Team): threshold crossings; unreviewed AI-written lines landing in a critical path; AI-written security findings and packages the registry does not know. Each names the commits. One push, at most one alert per kind.
  • Signed Authorship Bill of Materials (Team): a JSON export with a SHA-256 digest and an Ed25519 signature; keys published at /.well-known/grain-keys.json; verifiable at getgrain.dev/verify in the browser or with grain verify --bom offline.

6.6 — Security and dependency signals shipped

Provenance answers "who wrote it". Two analyses put that answer next to the lines that make vibe coding dangerous, in every report, the PR comment, the Cloud repo page and the agent loop. Neither is a vulnerability scanner, and both say so next to every finding.

  • Security: a small pattern set (secrets, TLS verification off, shell or SQL built from strings, unsafe deserialization, wildcard IAM, CORS to any origin, and similar) runs over the added lines of every commit. Each hit is joined with provenance and review evidence: AI-written or not, reviewed or not, in a critical path or not. Tests, fixtures, docs and the pattern file itself are skipped. When Claude Code writes such a line, grain hook claude tells the agent before the commit; grain attest warns on the commit. One pattern file, shared byte for byte by the Go engine and Cloud (a test enforces it).
  • Dependencies: the added lines of dependency manifests (package.json, go.mod, requirements*.txt, pyproject.toml, Cargo.toml, Gemfile) yield the packages a range introduced, attributed to the commit that first added them. With --check-registry (CLI, opt-in: local-first) or always in Cloud and the Action, grain asks npm, PyPI, the Go module proxy, crates.io and RubyGems whether the package exists and when it was created. A name the registry does not know is the slopsquatting seed; a package younger than 30 days that an agent reached for is worth a look. Only package names leave the machine.
  • Gates: security and dependencies under [policy], off | warn | block, default warn. The security gate fires on AI-written findings only (a dangerous human line is the SAST's job); the dependency gate on an unknown package, whoever added it, and on a young AI-added one.

08 GitHub Action

A thin wrapper around grain check. Runs on pull_request, posts/updates one sticky comment (AI share per path, policy lines, Security and Dependencies sections), sets the grain/provenance status, can request reviewers when flagged, and can push the scan to Cloud.

- uses: FrontTribe/grain@v1
  with:
    fail_on: never           # default; "policy" fails the check on attention or a blocking gate
    check_registry: 'true'   # default; ask the registries about dependencies the PR added (names only)
    request_review: 'false'  # true + reviewers/review_teams: request a human when flagged
    config:  .grain.toml
Default posture
The Action comments, does not block, out of the box. Gating is a deliberate opt-in twice over: fail_on: policy in the workflow, and security / dependencies = "block" in .grain.toml. This keeps first contact non-hostile.

10 Architecture

agent hook → ledger→ post-commit attest (signed note)→ git binary: commits · diffs · notes→ signals · classify · score→ outcomes · risk→ renderers (md · json · badge · pr) · push
  • Language: Go, standard library only; shells out to the git binary (decided against go-git: notes, blame and diff plumbing come for free).
  • Packages: gitlog, signal, features, classify, score, outcomes, risk, sign, report, config. Each signal extractor is additive.
  • No server for the CLI. Everything runs in the repo/CI. The badge is a static JSON committed or served by Cloud.
  • Cloud: Next.js on Vercel, Supabase (Postgres, RLS, one ingest function _grain_apply behind member and service-role wrappers), Stripe, a GitHub App (webhook, installation tokens, PR API), Resend for email. The engine pieces Cloud needs are mirrored in TypeScript (classify.ts, risk.ts, signing.ts, bom.ts); line hashes and canonical JSON are byte-identical across Go and TypeScript, guarded by a test that verifies a Cloud-signed BOM in Go.

11 Trust & privacy principles

  • Local-first. The free tool never transmits source code. All analysis is on-device / in-CI.
  • Signals, not verdicts. Output language is probabilistic and non-accusatory by contract.
  • Confidence caps on inference. Grain refuses to sound certain when it is guessing.
  • Explainability. grain explain shows the exact signals behind any classification.
  • Reproducibility. Scores are pinned to an engine + weights version in grain.json.
  • Tamper evidence, not surveillance. Attestations are signed and bound to their commit; anyone can verify them offline. The ledger stores hashes, never text. Nothing watches the developer; the record is written by the tooling at the moment of the edit.
  • Human override. grain annotate always wins over inference, and is signed like any other note.

12 Threat model & honest limits

ConcernRealityResponse
Stripping Co-Authored-By to hide AI useTrivially possible; falls back to weak inference.Grain is a transparency tool for cooperative repos, not anti-cheat. Stated plainly in docs; never over-claimed.
False positives on clean human codeReal risk with inference alone.Confidence cap + "signals" framing + never block by default. Declared signals preferred.
"Surveillance tool" perceptionReputational, could kill adoption.Non-goals are explicit; defaults are comment-only; positioning is maintainer-transparency, not dev-policing.
Adversarial rewriting to defeat heuristicsPossible with effort.Out of scope by design; Grain measures the honest signal that exists, not a guarantee.

Honesty as a feature
Naming these limits openly is part of the product. Overclaiming (an "AI detector that catches cheaters") is exactly what would trigger backlash and false-positive drama. Grain wins by being trustworthy, not omniscient.

13 Open-core boundary

The line: anything that runs on a single repo, locally, is MIT and free. Anything server-side, multi-repo, persistent, or policy-as-a-service is paid.

Licensing: core MIT (maximizes adoption + trust). Cloud is a hosted service on the same engine; its source lives in the same repository. The engine and the provenance format staying fully open is a feature, not a giveaway — it is what makes the numbers credible. Why Free gives up alerts and the signed export: Free shows you everything; Team is for being told, and for handing the numbers to someone else.

17 Decisions taken (the v0.1 open questions)

  1. Language: Go, standard library only, shelling out to git. decided
  2. Forge scope: GitHub first (App, PR API); the core is git-native so GitLab / Bitbucket are a scanner away. decided
  3. Local model: deferred; the lexical classifier plus per-repo calibration is the inference layer, and the study says a global model wouldn't have generalized anyway. decided
  4. Name & domain: grain, getgrain.dev, GitHub org FrontTribe, npm shim npx grain, Homebrew tap, Scoop bucket. decided
  5. Badge hosting: shields endpoint over a committed grain.json, plus a per-repo public badge from Cloud. decided
  6. Monetization: no waitlist; a free tier on day one, Team at $29 per workspace, Audit from $199. Alerts and the signed export are the upgrade reasons. decided
  7. Still open: which agent gets the second capture hook; per-seat vs per-workspace pricing once teams exceed 20 seats; whether convention deviation earns its place as a signal.
